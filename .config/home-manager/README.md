# Home Manager Configuration

Standalone [Home Manager](https://nix-community.github.io/home-manager/) setup (flake-based) for managing user packages and dotfiles on this machine. Standalone means Home Manager runs on its own, not as a NixOS module, so this works on any Linux distro with Nix installed.

Currently configured in **multi-user mode**: one shared base module plus optional per-user overrides.

## Layout

```
.
├── flake.nix          # Entry point. Defines inputs and the homeConfigurations
├── flake.lock         # Pinned nixpkgs / home-manager revisions. Do not delete
├── common.nix         # Shared config applied to every user
├── home.nix           # Legacy single-user config. Currently unused (see below)
└── users/
    ├── developer.nix  # Per-user overrides for `developer`
    ├── chanjl.nix     # Per-user overrides for `chanjl`
    └── brina.nix      # Orphaned. No matching entry in flake.nix, so never loaded
```

## How it fits together

`flake.nix` defines a `mkUser` helper that composes each user's config from three layers:

1. `common.nix` - shared across all users
2. An inline block setting `home.username` and `home.homeDirectory = "/home/<username>"`
3. `users/<username>.nix`, but only if that file exists (guarded by `builtins.pathExists`)

Those are then exported as named configurations:

```nix
homeConfigurations = {
  "developer" = mkUser "developer";
  "chanjl"    = mkUser "chanjl";
};
```

The important consequence: **dropping a file into `users/` is not enough**. A user only exists if it is also listed in `homeConfigurations`. That is exactly why `users/brina.nix` does nothing today.

## Usage

Apply a configuration (run as that user, from this directory):

```sh
home-manager switch --flake .#developer
```

Other common commands:

```sh
home-manager switch --flake .#chanjl     # apply for chanjl
nix flake update                         # bump nixpkgs + home-manager, rewrites flake.lock
nix flake check                          # evaluate without applying
home-manager generations                 # list previous generations
/nix/store/.../activate                  # roll back by activating an older generation
```

After `nix flake update`, always `switch` and confirm things still work before relying on it. The lockfile is the only thing keeping builds reproducible.

## What is configured where

### `common.nix` (all users)
- Package: `neofetch`
- `programs.home-manager.enable` so Home Manager manages itself
- `dconf.enable`, which grants permission to write the GNOME dconf database
- GNOME custom keybinding: `<Super>Return` launches `ghostty`

### `users/developer.nix`
- `home.stateVersion = "25.11"`
- Packages: `htop-vim`, `bat`, `cmake-language-server`, `gdown`, `gh`, `yt-dlp`, `showmethekey`, `python3Packages.openusd`

### `users/chanjl.nix`
- `home.stateVersion = "25.05"`
- Packages: `htop-vim`

## Adding a new user

1. Create `users/<username>.nix` (copy `chanjl.nix` as a minimal starting point)
2. Add the entry to `flake.nix`:
   ```nix
   "<username>" = mkUser "<username>";
   ```
3. Apply: `home-manager switch --flake .#<username>`

Set `home.stateVersion` in the new file to the Home Manager release current *at the time the user is first set up*, then leave it alone.

## About `home.nix` and single-user mode

`home.nix` is the original scaffold generated by `home-manager init`, from before this setup went multi-user. It is **not imported by anything** in the active config, and its contents (username, `neofetch`, `programs.home-manager.enable`) are already covered by `common.nix` plus `users/developer.nix`.

`flake.nix` still carries a commented-out single-user `outputs` block (roughly lines 14-31) that references `./home.nix`. To go back to single-user, uncomment that block and comment out the multi-user `outputs` block below it. Only one `outputs` attribute can be active at a time.

If you commit to multi-user, `home.nix` and the commented block can both be deleted. Keeping them costs nothing but is a recurring source of "wait, which file is actually live?" confusion, so decide one way or the other.

## Notes and gotchas

- **`home.stateVersion` is not a version to keep current.** It records the release a user's config was first written against and preserves backwards-compatible behaviour. The mismatch between `developer` (`25.11`) and `chanjl` (`25.05`) is correct and should not be "fixed".
- `nixpkgs` tracks `nixos-unstable`, so `nix flake update` can pull in breaking changes. `flake.lock` is what protects you between updates.
- Both user files contain fully commented-out `home.file` and `home.sessionVariables` blocks left over from the scaffold. They are inert boilerplate, kept as inline examples.
- Every package here is user-scoped. System-level configuration (drivers, services, bootloader) is not managed by this directory.
